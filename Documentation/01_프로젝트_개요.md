# 부스 운영용 로컬 멀티 미니게임 (Mini Party) — 프로젝트 개요

## 한 줄 요약

Unity 2D URP 템플릿 기반의 **1~4명 로컬 동시 플레이** 아케이드 미니게임 모음이다. **플레이어 번호(1P~4P)**·HP·연승 등 세션 데이터는 `PartySession`이 들고, **운영자(키보드)**가 메뉴·시작·진행을 담당한다.  
미니게임마다 화면 배치·슬롯 패널 유무·입력 규칙은 **게임별로 다르다**(슬롯 UI가 없는 게임도 가능). 부스 USB 패드는 `SlotGamepad`·`BoothUsbGamepadLayout`로 읽는다.

## 미학·톤

- 비시바시 / 마리오 파티 스타일의 밝고 빠른 템포  
- 관전자가 상태를 한눈에 볼 수 있도록 HUD 중시  
- 오락실 부스 운영을 전제로 한 즉시 플레이 플로우

## 입력 계층

- **운영자**: `OperatorInputService` — `↑/↓`만 목록 이동, **Enter / 키패드 Enter** (메뉴 이동·시작·일부 미니게임 진행 확인).
- **플레이어 패드**: `SlotGamepad` — 코드상 `Joystick.all[playerIndex]`로 읽는다. Start·Select 등 공용 버튼은 `BoothUsbGamepadLayout`. **게임별 버튼 의미**는 각 `05_*.md` (예: OIIA O/I/A → `05_OIIA.md` §6). 부스에서는 **연결된 패드를 보고 자리에 맞게 옮기면** 된다.
- **개발자 키보드 디버그**: `DeveloperKeyboardGamepadDebug` — `Ctrl` 토글 시 **1P만** `BoothUsbSlotInput` 경유 키보드 에뮬 (WASD·QE·키패드7845·V/B → 부스 패드). 상세는 `03_Booth_USB_Controller_매핑.md`.

## 파티·세션 (게임 전반)

### 플레이어 번호

- 참가자는 **PLAYER 1 ~ PLAYER 4** (코드 인덱스 **0 ~ 3**).
- HP·READY·연승·`MinigameSessionReport` 점수 등은 **`PartySession`의 플레이어 번호에 귀속**된다. 씬을 바꿔도 같은 번호의 데이터가 이어진다.
- 메인·Result 화면의 「자리」UI는 **그 플레이어 번호를 보여 주는 표시**일 뿐이다. 미니게임마다 패널 배치·개수·유무는 **게임마다 다르거나 없을 수 있다**.

### 세로 4분할 레이아웃 (이 형식을 쓰는 화면만)

- **1P → 2P → 3P → 4P** 순으로 **왼쪽부터** 배치한다 (OIIA·메인·Result 등 세로 4칸 UI를 쓰는 경우 공통).
- 플레이어 번호와 패드 맞춤은 **부스 운영**에서 연결 상태를 확인하고 **패드를 옮겨** 맞춘다. USB 꽂는 순서를 문서·기획에서 걱정할 필요 없다.

### HP · Result

- 미니게임 **플레이 중**에는 HP를 깎지 않는다. **Result 씬 `HpProcess`**에서만 `ApplyHpDelta(-1)`.
- **본게임 한 판당** 조건 충족 시 **최대 HP −1**. **연습 판**은 HP 계산·감소 없음.
- **어떤 조건에서 HP가 깎이는지**는 미니게임마다 다르다 (예: OIIA → `05_OIIA.md`).

### 연습 → 본게임

- 설계상 **모든 미니게임**은 **연습 → 본게임** 순서를 거친다. 연습 스킵 옵션은 없다.
- 미구현 게임(RBC 등)에 연습이 없는 것은 **미완성**이지 예외가 아니다.
- 구현 방식은 **게임별** — OIIA는 `05_OIIA.md` §3.

### 씬 Inspector 우선

플레이 테스트 후 **씬 YAML에 저장된 값**이 정답이다. 메인 메뉴 Inspector는 `04_메인메뉴.md`, 미니게임별 차이는 각 `05_*.md` §15 등에서 본다.

## 메인 메뉴 — 플레이어 자리 HUD (`GameFlowDirector`)

메뉴·Result의 4칸 UI는 **플레이어 번호 1~4** 표시용이다. 상세는 `04_메인메뉴.md`.

- **Line1**: `PLAYER 1` ~ `PLAYER 4`.
- **Line2** (상태별): `EMPTY` / `ACTIVE` / `READY` 등 (JOIN·READY 문구·색).
- **Line3**: **`WIN {WinStreak}`**.
- **Start**: `EMPTY`에서 JOIN, `ACTIVE`/`READY` 토글. **전원 READY** 후 운영자 Enter로 미니게임 시작.
- Result 복귀 후 생존(`HP > 0`) 플레이어는 **`ACTIVE` 유지**. `HP ≤ 0`만 `EMPTY`.
- **게임 중 조인 불가** — JOIN은 메인 메뉴 전용.

## Results 씬 (공통 결과 화면)

### 플로우 (요약)

```text
MainMenu → 미니게임(연습/본) → [종료·페이드 등] → LoadScene("Results")
  → Fade In → 등수 → HP → GAME OVER(해당 시) → Ready → Enter → MainMenu
```

- `MinigameSessionReport` — `FinalScore`, `HpLostThisSession`, `Rank` 등. 게임별 `IResultMinigameFlavor`로 장식 가능.
- Result 종료 시 `FinalizeLobbyAfterMinigame` → 생존 플레이어 `ACTIVE`, 탈락 `EMPTY`, 연승 갱신.
- 미니게임별 종료 연출·HP 판정 규칙은 각 `05_*.md` 참고.

### 연출 단계 (`ResultPhase`)

| 단계 | 내용 |
|------|------|
| `IntroFade` | Fade In, 참가 플레이어 `PLAYER n` 표시 |
| `RankingReveal` | 1등부터 등수·점수 공개 |
| `HpProcess` | HP 감소 연출 |
| `GameOver` | HP 0 처리 |
| `Ready` | START·Enter로 메인 복귀 |

**연습** 라운드는 등수·HP·GAME OVER 축소 후 바로 `Ready`.

Result 씬 UI·프리팹·스크립트 상세는 기존 구현 참고 (`ResultFlowController`, `ResultSlotPanel` 등). 필요 시 별도 Result 문서로 분리 가능.

### 미구현·후속

- 게임별 `IResultMinigameFlavor` 장식 강화.
- `rankRevealClip` / `hpHitClip` 등 Inspector 오디오 연결.

Inspector (`SnesPlayerFaceButtons`): `playerIndex`(0=1P…3=4P) · `buttonY/X/A/B` · `syncHeldFromPadEveryFrame`(기본 true).

### Prefab (실명)

| Prefab | 역할 |
|--------|------|
| **`Buttons_ABXY`** | **유일 완제품.** `SnesPlayerFaceButtons` + 자식 4버튼(인라인). Variant·단품 Prefab **없음** |

자식 이름 `BtnY`/`BtnX`/`BtnA`/`BtnB`는 `AutoWireFromChildren` 규칙과 맞춰 둔다. SuperFamicom **`*Press.png`** 가로 시트 4프레임: **앞 2 = 눌림**, **뒤 2 = 해제**(역재생 아님). Sprite Editor Multiple·Grid 13×15 → SpriteSet **`pressFrames`** 0~3 좌→우. Held = `*Pressed` / A는 `APresseed`. Visual: **`framesPerSprite`**·`pressFrameCount`·`heldScale` — 단일 버튼은 `SnesControllerButtonVisual`, 4버튼 묶음은 **`Buttons_ABXY`** 루트 `SnesPlayerFaceButtons` **애니 타이밍**에서 일괄 조절(기본 **`framesPerSprite` 16**). **강조**(`*Highlighted`)는 `SetHighlighted` / `SetHighlightedOnly` 호출 시에만(패드 홀드와 무관). 현재 미니게임 미연동 시 Play에서는 Idle/Press만 보임.

### 사용 원칙

- **씬에 넣을 때**는 **`Buttons_ABXY`**만 배치한다.
- **1P~4P용 Prefab을 나누지 않는다.** 같은 **`Buttons_ABXY`**를 인스턴스하고 Inspector **`playerIndex`만** 0~3으로 둔다.
- 홀드 애니: `syncHeldFromPadEveryFrame == true`이면 패드 폴링을 드라이버가 처리.
- 강조(타겟): 미니게임이 `SetHighlighted` / `SetHighlightedOnly` / `ClearAllHighlights` 호출. 필요 시 `SetPlayerIndex`, `ResetAllVisuals`, `GetVisual`.
- 미니게임이 Held까지 직접 돌릴 때만 `syncHeldFromPadEveryFrame`을 끄고 `TickHeldFromPad`를 호출한다.

### 에셋 스타일 (두 라인)

| 라인 | 시각 | SpriteSet | Prefab |
|------|------|-----------|--------|
| **Color** | Press 시트 **4프레임 애니** | `idle` · `highlighted` · **`pressFrames[]`** · `held` | **`Buttons_ABXY`** 등 |
| **2D (무애니)** | **Unpressed ↔ Pressed 즉시** · **강조 유지** | `idle` · `highlighted` · `held` · **`pressFrames` 비움** | **Color Prefab 복제·일부만 변경** (`instantHoldVisual`) |

- C#·드라이버(`SnesPlayerFaceButtons` 등) **동일**. 2D는 루트 **`instantHoldVisual`** ✅.
- 기존 `2D_*` 별도 Prefab·Press 슬라이스 작업은 **폐기**.
- 2차 후보: Full Controller
